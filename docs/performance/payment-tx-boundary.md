# 결제 승인의 트랜잭션 경계 — 결제사 응답 대기가 좌석 홀드에 주는 영향

> 측정일 2026-10-04. 하네스: `src/test/java/com/placeholder/benchmark/PaymentTxBoundaryBenchmark.java`
> 실행: `./mvnw.cmd test -Dtest=PaymentTxBoundaryBenchmark -DfailIfNoSpecifiedTests=false`
> (클래스명이 `*Benchmark`라 CI 기본 테스트에 포함되지 않는다)

## 1. 질문

결제사 호출을 트랜잭션 **안**에서 하면, 결제사 응답을 기다리는 동안 DB 커넥션을 점유해
무관한 경로(좌석 홀드)가 영향을 받는다 — 이것이 숫자로 얼마인가.

## 2. 비교군

| | 구조 |
|---|---|
| **A** | 주문 행 잠금 → 결제사 호출 → 적립을 **하나의** `@Transactional`에서 수행 (테스트 전용 대조군, 운영 코드에 없음) |
| **B** | 현재 구조 — 짧은 검증 트랜잭션 → **트랜잭션 밖** 결제사 호출 → 짧은 적립 트랜잭션 |

적립 로직은 두 비교군 모두 운영 코드의 `PaymentSettlementService.settle`을 그대로 쓴다. 차이는 경계뿐이다.
A는 주문 행을 **먼저** 잠그는 형태다. 잠금을 결제사 호출 뒤로 미루는 변형이라면 커넥션 점유는 같고
주문 행 락 보유 구간만 짧아진다(실험 2의 A 수치가 이 선택에 의존한다).

## 3. 측정 조건

| 항목 | 값 |
|---|---|
| CPU / RAM | AMD Ryzen 5 5600 (6코어, 논리 12) / 31.9GB |
| DB | MySQL 8.0 Testcontainers (같은 PC) |
| 경로 | 인프로세스 서비스 호출 (HTTP 계층 제외) |
| Hikari | max = min = **10**, connectionTimeout 30,000ms |
| 결제사 | `TossPaymentClient`를 응답 지연 0 / 500 / 2000ms인 가짜로 교체 |
| 부하 (실험 1) | 결제 승인 20건 동시 + 좌석 홀드 스레드 20개 연속 요청. 측정 구간 = 결제 20건 완료까지 |
| 반복 | 칸마다 3회 중앙값, 비교군별 워밍업 1회 폐기, 비교군 교대 실행 |
| 풀 샘플링 | `HikariPoolMXBean` 50ms 간격 |

**계측 (운영 코드 무수정).** HikariDataSource를 감싸는 래퍼가 호출 스레드 단위로 기록한다.
- `getConnection()` 소요 → 커넥션 획득 대기
- 커넥션 획득 ~ 반납 → 보유 시간 (트랜잭션 시작~커밋을 바깥에서 감싸는 값)
- `payment_orders … for update` 실행 소요 → 주문 행 락 대기

결제 사용자와 홀드 사용자는 서로 다르고, 홀드는 좌석마다 한 번만 잡는다. 두 작업이 공유하는 자원은
커넥션 풀뿐이다.

## 5. 관찰 (해석 전 사실)

- **지연 0ms에서도 풀은 포화 상태였다.** 스레드 40개가 커넥션 10개를 나눠 써서 대기 스레드 max가
  모든 칸에서 24~30이다. A/B 차이는 max가 아니라 **평균**(A 23~24, B 11~12)에 나타난다.
- **홀드 p50은 지연 2000ms에서도 A·B가 비슷하다(32.4 / 28.8ms).** 차이는 p95·p99와 처리량에 있다.
  홀드 스레드는 응답을 받아야 다음 요청을 보내는 폐쇄 루프라, 커넥션이 막힌 구간에는 완료 건수
  자체가 적고 풀린 순간에 빠른 홀드가 몰린다. 요청 단위 p50은 막힌 시간을 과소 대표한다.
- **커넥션 획득 후 실행 시간은 B가 더 길다**(500·2000ms에서 p95 A 18~21 / B 31~33ms).
  B가 같은 시간에 홀드를 3~14배 더 처리했다. 원인은 확인하지 않았다.
- **B는 결제 1건이 트랜잭션 2개를 쓴다.** 지연 0ms에서는 결제 1건당 커넥션 보유 합계(27.1 / 19.7ms)와
  결제 지연 p50(128 / 72ms) 모두 B가 길다.
- A 2000ms의 한 회차는 p99가 4053.8ms였다(다른 회차 2102ms). 일부 홀드가 결제 두 묶음 동안 연속으로
  커넥션을 얻지 못했다.
- 지연 0ms 칸은 측정 구간 200ms 안팎, 홀드 70~120건이라 A·B 차이는 잡음 범위다.
